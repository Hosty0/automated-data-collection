# Лабораторная работа № 5
## Промышленный краулинг: Scrapy-проект и оркестрация в n8n
**Вариант 3**

Демонстрация работы представлена в файле README.md

### 1. Цель и источник
Цель работы — разработать краулер на Scrapy с пагинацией и двухуровневым обходом, обработкой данных в Item Pipeline, сохранением в SQLite и воспроизвести сокращённый конвейер в n8n.

Источник [Quotes to Scrape](https://quotes.toscrape.com/). Первый уровень - страницы списка цитат. Второй уровень - страницы авторов. Для каждой цитаты сохраняются текст, автор, теги, дата и место рождения автора, биография, URL автора и URL страницы списка.

### 2. Архитектура Scrapy
Spider формирует начальные запросы и обрабатывает HTML. В `parse()` извлекаются карточки цитат и ссылка на следующую страницу. Цитаты группируются по URL автора: для одного автора создаётся один запрос, а список цитат передаётся в `parse_author()` через `cb_kwargs`. Это важно, поскольку Scheduler Scrapy дедуплицирует одинаковые URL и повторные запросы к одной странице автора не должны терять контекст остальных цитат.

В `parse_author()` извлекаются `.author-born-date`, `.author-born-location` и `.author-description`. При отсутствии обязательных данных карточка пропускается с увеличением счётчика. Сетевые ошибки учитываются через `errback`. Метод `closed()` сохраняет статистику в отдельный `data/stats_NNN.json`.

Путь данных: Spider → Engine → Scheduler → Downloader и middleware → Response → Spider → Items → Item Pipeline → SQLite.

### 3. Item Pipeline и хранение
Реализованы четыре звена с приоритетами:
1. **ValidationPipeline (100)** - проверяет обязательные поля `quote`, `author`, `tags`, `author_url`; отбрасывает невалидные записи через `DropItem` и считает `dropped/missing_fields`.
2. **CleanPipeline (200)** - удаляет лишние пробелы, нормализует теги к нижнему регистру. Дата рождения сохраняется в исходном текстовом представлении сайта, поскольку произвольное преобразование без подтверждённого формата может исказить значение.
3. **DeduplicationPipeline (300)** - удаляет повтор по бизнес-ключу «автор + цитата» и считает `dropped/duplicates`.
4. **SQLitePipeline (400)** - использует одно соединение на паука, буфер и `executemany`; уникальное ограничение SQLite дополнительно защищает от повторов между запусками.

### 4. Вежливость, надёжность и наблюдаемость
Установлены `ROBOTSTXT_OBEY=True`, учебный User-Agent, `CONCURRENT_REQUESTS=8`, `CONCURRENT_REQUESTS_PER_DOMAIN=2`, `DOWNLOAD_DELAY=0.75`, `AUTOTHROTTLE_ENABLED=True`, `AUTOTHROTTLE_TARGET_CONCURRENCY=1.0`, тайм-аут 25 секунд и три повтора для 429/5xx. Предусмотрены `DEPTH_LIMIT=3`, `CLOSESPIDER_ITEMCOUNT=300`, `CLOSESPIDER_PAGECOUNT=1000` и `CLOSESPIDER_ERRORCOUNT=30`. HTTP-кэш включён для разработки.

Для демонстрации возобновления применяется `JOBDIR=jobstate/run1`: после остановки повторный запуск с тем же каталогом использует сохранённую очередь и фильтр посещённых запросов.

### 5. Качество данных
Скрипт `quality/quality_report.py` рассчитывает число строк, полноту каждого поля и распределение цитат по авторам и тегам. `quality/smoke_check.py` сравнивает два файла статистики: предупреждает при падении количества элементов более чем на 20%, а также при доле пустых обязательных значений выше 5%.

### 6. Эквивалентный конвейер n8n
Экспорт `nocode/workflow.json` предназначен для импорта в n8n и демонстрирует сбор подмножества (до 30 записей): Schedule Trigger, HTTP Request, извлечение HTML, разбиение элементов, цикл по цитатам, запрос страницы автора, извлечение полей, Wait, удаление дублей и нормализация. Для устойчивой эксплуатации следует включить Retry On Fail на HTTP-узлах и Error Trigger для уведомлений. После импорта требуется проверить версии узлов и селекторы в установленной версии n8n.

### 7. Сравнение и выводы
| Метрика | Scrapy | n8n |
|---|---:|---:|
| Время разработки, мин | 120 | 60 |
| Записей собрано | 52| 60 |
| Время прогона, с | 20 | 60 |
| Записей в минуту | - | - |
| Число сетевых запросов | - | - |
| Трафик, МБ | - | - |
| Дедупликация запросов | Встроенный фильтр дубликатов | Настраивается отдельными узлами |
| Возобновление после сбоя | JOBDIR | - |
| Расписание и оповещения | - | Встроенные триггеры и интеграции |
| Оценка усилий на поддержку (1–5) | 3 | 3 |

Для разового обхода 500 страниц целесообразен Scrapy, если есть много ссылок и требуется надёжная очередь. Для ежедневного обхода 40 000 страниц — Scrapy с JOBDIR, БД и мониторингом. Для сотни страниц с отправкой отчёта в мессенджер удобен n8n. Гибридный контур: n8n запускает Scrapy (например, через Scrapyd API), отслеживает завершение, читает агрегаты из БД и отправляет отчёт/оповещение.

### 8. Риски и правовые аспекты

Сбор ограничен учебным сайтом. Соблюдаются `robots.txt`, задержки и AutoThrottle; не предпринимается обход капчи или антибот-защиты. Не собираются специальные категории персональных данных. При переносе решения на реальные сайты необходимо проверить условия использования, правовое основание обработки персональных данных (152-ФЗ/GDPR, где применимо), минимизировать объём и период хранения.
