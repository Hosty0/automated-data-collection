# Отчёт по лабораторной работе № 3

## 1. Цель и вариант
**Цель работы:** реализовать воспроизводимый сбор данных через REST API двумя способами - программно на Python и в no-code среде

**Вариант 3:**

* API обогащения: Open Library Authors

## 3. Архитектура пайплайна

* **Источник (Open Library):** Настройка сессии `requests.Session` с передачей заголовков `User-Agent` и `Accept`
* **Сбор:** Реализация пагинации `page`/`limit`, ограничение скорости (rate limit), обработка ошибок и повторов
* **Нормализация:** Использование `pandas.json_normalize` с параметром `sep='_'` и развёртывание вложенного массива авторов
* **Обогащение:** Соединение (`merge`) основной таблицы с эндпоинтом `/authors` по ключу `author_key`
* **Проверка качества:** Оценка полноты данных, удаление дубликатов, типизация дат и чисел, логические проверки
* **Хранение:** Экспорт результатов в `data_clean.csv`, `data_raw.jsonl`, `collection_log.csv`, `state.json`

## 4. Принятые решения по пагинации, лимитам и повторам

* **Пагинация:** Параметр `page` инкрементируется циклично. Предохранитель установлен на `max_records=300` и `max_pages=10`. Остановка происходит при достижении лимита записей, пустой странице или исчерпании `numFound`.
* **Лимиты:** Перед каждым запросом установлена пауза `time.sleep(1.5)` сек для соблюдения этики сбора.
* **Повторы:** Реализованы через `urllib3.util.retry.Retry`. Экспоненциальная задержка применяется только для кодов 429 и 5xx. Для ошибок 4xx повторы отключены.
* **Журнал сбора:** Запросы логируются в `collection_log.csv` с сохранением номера страницы, URL, параметров (JSON), кода ответа, количества записей, длительности и отметки времени.
* **Инкрементальность** last_page фиксирует номер последней успешно обработанной страницы. При следующем запуске читается это значение, запрос к API начинается с last_page + 1. Уникальные идентификаторы авторов выступают "водяным знаком". Если ключ автора присутствует в словаре, значит профиль уже выгружен, запрос по данному автору пропускается. 

## 5. Результаты проверки качества данных

* **Собрано:** Более 300 сырых записей.
* **Дубликаты:** По составному ключу `key` + `author_key` найдены и удалены 2cдубликата.
* **Полнота полей:** Поля `key`, `title`, `author_key` заполнены на 100%. Полнота дат рождения варьируется в зависимости от заполненности карточек авторов в Open Library.
* **Проверки логики:**
  * *Корректный год издания:* Записей с датой больше текущей даты нет.
  * *Осмысленное название:* Заголовки без пустого наименования.
* **Инкрементальность:** Файл `state.json` хранит массив `processed_keys` и номер последней страницы. Повторный запуск скрипта не создает дубликатов в сырых данных.

## 6. Сравнение подходов

| Критерий | Python | n8n |
| :--- | :--- | :--- |
| Время разработки, мин | 180 | 60 |
| Число собранных записей | 300 | 60 |
| Время выполнения одного прогона, с | 45 | 5 |
| Поддержка пагинации | Полная | Настрйка Pagination в HTTP Requests |
| Обработка ошибок и повторов | Retry-After | Через IF и Stop and Error |
| Воспроизводимость (Git, экспорт) | Полная (репозиторий) | Экспорт JSON-схемы |
| Стоимость при 100 прогонах в месяц | Бесплатно> | Бесплатно при локальном запуске |
| Порог входа (субъективно 1–5) | 4 | 1 |

**Вывод:** Использование Python оправдано для сложного сбора с пагинацией, обогащением из нескольких эндпоинтов. Инструменты n8n идеально подходят для настройки простых выгрузок.

## 7. Правовая и этическая оценка

Сбор данных осуществляется с соблюдением этических норм парсинга: установлены явные паузы между запросами и передан идентифицирующий заголовок `User-Agent`. Источник (Open Library) предоставляет данные открыто, регистрация и ключи не требуются. 

Собираемые метаданные книг и информация о писателях являются общедоступными библиографическими сведениями. Данные о фактах биографии публичных фигур (писателей) не требуют согласия на обработку согласно положениям 152-ФЗ «О персональных данных», так как они подлежат опубликованию в открытых источниках. Срок хранения собранного аналитического датасета не ограничен.
